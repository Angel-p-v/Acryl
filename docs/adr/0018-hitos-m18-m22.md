# ADR 0018: Hitos M18–M22 — TUI metadatos, sincronización, shell-completion, E2E y cobertura · v2.2

**Fecha:** 2026-10-25  
**Estado:** Aceptado  
**Autor:** Coronel

## Contexto

media-manager v2.2 cierra los hitos M18 a M22 tras M17 (sincronización automática de metadatos con TTL). Los hitos restantes son:

| Hito | Contenido                                                                   |
| ---- | --------------------------------------------------------------------------- |
| M18  | TUI con metadatos visuales (póster, sinopsis, calificación, año, proveedor) |
| M19  | Sincronización en segundo plano de metadatos (watch, TTL, rate-limiting)    |
| M20  | Auto-completado de shell (bash, zsh, fish)                                  |
| M21  | E2E interactivos con TTY real (node-pty)                                    |
| M22  | Mejorar cobertura de pruebas (watch, play, watcher)                         |

Todos los hitos M0–M17 están completados y mergeados en `main`.

## Decisión

### M18 — Tecla `m` para navegar al panel de detalles

Se añade el keybinding `goToDetails: 'm'` a `defaultConfig.keybindings`. Al pulsar `m` en el listado de la TUI, el panel de detalles se muestra u oculta alternando el estado `detailsVisible`. Cuando no hay metadatos, el panel muestra la opción para obtenerlos desde TMDB/TVDB (tecla `r`).

- Archivo modificado: `src/core/config/defaults.ts` (añade `goToDetails: 'm'`)
- Archivo modificado: `src/ui/App.tsx` (estado `detailsVisible`, handler `handleGoToDetails`)
- Archivo modificado: `tests/unit/config/schema.test.ts` (verifica el atajo por defecto)
- Documentación: README.md (tabla de atajos TUI)

### M19 — Rate-limiting y auto-refresco de metadatos al iniciar

**Rate-limiting:** se crea `src/core/metadata/rateLimiter.ts` con un `RateLimiter` por proveedor que aplica una ventana deslizante de peticiones:

| Proveedor | Límite | Ventana |
| --------- | ------ | ------- |
| TMDB      | 40 req | 10 s    |
| TVDB      | 10 req | 10 s    |

Antes de cada llamada a la API (`searchTmdb`, `getTmdbDetails`, `searchTvdb`, `getTvdbDetails`), `MetadataService` invoca `rateLimiters.<provider>.waitForSlot()` para respetar el límite de tasa.

**Auto-refresco:** al montar la TUI en la vista `library`, si hay metadatos expirados y un proveedor configurado, se ejecuta `library.refreshExpiredMetadata()` automáticamente en lugar de solo mostrar un aviso estático.

- Archivo nuevo: `src/core/metadata/rateLimiter.ts`
- Archivo modificado: `src/core/metadata/service.ts` (usa rateLimiters antes de cada llamada API)
- Archivo modificado: `src/ui/App.tsx` (auto-refresh en `useEffect` de montaje)
- Archivo nuevo: `tests/unit/metadata/rateLimiter.test.ts` (4 tests del RateLimiter)

### M20 — Auto-completado de shell

El comando `mm completion <shell>` ya existía en `src/cli.tsx` y `src/commands/completion.ts` generando scripts para bash, zsh y fish. Falta la documentación de usuario.

- Documentación: README.md (sección "Autocompletado de shell" con instrucciones de instalación por shell)

### M21 — E2E interactivos con TTY real

Ya se había integrado `node-pty` en `tests/e2e/tui.e2e.test.ts` con tests de navegación por TUI con teclas reales y reproducción desde TUI. No se requieren cambios de código.

- Archivo existente: `tests/e2e/tui.e2e.test.ts` (30 tests, pasan en CI)

### M22 — Cobertura de pruebas

Ya existen tests para `launcher.ts`, `watcher.ts`, `watch.ts` y `service.ts`. La cobertura global con los tests actuales (excluyendo el test de estrés pre-existing en ARM64) cumple los umbrales:

| Métrica    | Valor   | Umbral |
| ---------- | ------- | ------ |
| Statements | 89.65 % | ≥ 85 % |
| Branches   | 81.31 % | ≥ 80 % |
| Functions  | 92.25 % | ≥ 85 % |
| Lines      | 91.81 % | ≥ 85 % |

No se requieren cambios de código adicionales.

## Alternativas consideradas

| Alternativa                                                       | Por qué se descarta                                           |
| ----------------------------------------------------------------- | ------------------------------------------------------------- |
| Rate-limiting global compartido entre proveedores                 | Cada proveedor tiene límites distintos de API; mejor isolados |
| Refrescar metadatos al iniciar siempre (sin verificar expiración) | Llamadas innecesarias a la API y consumo de rate limit        |
| Auto-completado solo para comandos principales                    | El usuario espera completar subcomandos y opciones también    |

## Consecuencias

### Positivas

- La TUI ofrece experiencia visual completa con metadatos de TMDB/TVDB
- Las llamadas a APIs externas respetan los límites de tasa de cada proveedor
- Los metadatos se refrescan automáticamente al abrir la biblioteca sin intervención del usuario
- El autocompletado de shell mejora la UX en terminal
- La cobertura de pruebas cumple los umbrales definidos en `vitest.config.ts`

### Negativas / Riesgos

- La primera apertura de detalles puede ser lenta si hay que descargar de la API externa
- Dependencia de APIs externas que pueden estar caídas o tener rate limits estrictos
- El test de estrés de 100 000 entradas en ARM64 excede el presupuesto de rendimiento (pre-existing, no bloqueante)
